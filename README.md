# سامانه مدیریت خشکشویی

پذیرش، کارگاه، تحویل و مدیریت چندشعبه‌ای خشکشویی؛ فارسی، راست‌به‌چپ و تقویم جلالی.
مسیر کامل پروژه، معماری و فازبندی در [`ROADMAP.md`](ROADMAP.md) است.

| پوشه | محتوا |
|---|---|
| `backend/` | API با Laravel 13 (مونولیت ماژولار در `app/Modules`) |
| `frontend/` | پنل با Next.js 16، React 19 و Ant Design 6 |
| `docs/api/openapi.json` | قرارداد API که از کد بک‌اند تولید می‌شود؛ نوع‌های TypeScript فرانت از همین فایل ساخته می‌شوند |
| `compose.yaml` | اجرای کل سامانه با Docker |

## اجرا با Docker

```bash
cp .env.example .env
```

```bash
echo "APP_KEY=base64:$(openssl rand -base64 32)" >> .env
```

```bash
docker compose up --build -d
```

```bash
docker compose exec api php artisan db:seed --force
```

پنل روی <http://localhost:3000> باز می‌شود و سرور سوکت (Reverb، برای به‌روزرسانی زنده تابلوی تولید) روی پورت ۸۰۸۰. دستور آخر داده نمونه می‌سازد؛ برای راه‌اندازی واقعی به‌جای آن `docker compose exec api php artisan laundry:install` را اجرا کنید تا کسب‌وکار، شعبه اول و حساب مالک را بپرسد.

## اجرای محلی برای توسعه

پیش‌نیازها: PHP 8.4 با افزونه‌های `pdo_pgsql` و `redis`، Composer، Node.js 22، PostgreSQL 17 و Redis 7.

بک‌اند (روی پورت ۸۰۰۰):

```bash
cd backend && composer install && cp .env.example .env && php artisan key:generate
```

```bash
php artisan migrate --seed
```

```bash
php artisan serve
```

تابلوی تولید بدون سرور سوکت هر ۱۵ ثانیه تازه می‌شود. برای به‌روزرسانی زنده در `.env` مقدار `BROADCAST_CONNECTION=reverb` بگذارید و در کنار `serve` این‌ها را هم اجرا کنید (دومی هشدار عقب‌افتادگی را می‌فرستد):

```bash
php artisan reverb:start
```

```bash
php artisan schedule:work
```

فرانت (روی پورت ۳۰۰۰؛ درخواست‌های `/api` و `/sanctum` را به بک‌اند می‌فرستد):

```bash
cd frontend && npm ci && cp .env.example .env.local
```

```bash
npm run dev
```

پنل را همیشه از <http://localhost:3000> باز کنید، نه از پورت ۸۰۰۰؛ نشست ورود فقط برای نشانی‌های `SANCTUM_STATEFUL_DOMAINS` برقرار می‌شود.

### پرتال مشتری

پرتال مشتری روی <http://localhost:3000/my> است و ورودش با کد پیامکی است. برای توسعه محلی در `backend/.env` مقدار `OTP_FIXED_CODE=12345` بگذارید تا کد همیشه همین باشد (در محیط عملیاتی نادیده گرفته می‌شود). مشتریان نمونه همان شماره‌های `DemoCustomerSeeder` هستند، مثلاً `09121112233`. داده نمونه دو محدوده سرویس در تهران (ونک و اطراف برای شعبه مرکزی، غرب برای شعبه غرب) و برنامه هفتگی جمع‌آوری دارد.

مشتری در «سفارش جدید» نشانی (فقط نشانی‌های داخل محدوده)، بازه جمع‌آوری و اقلام را انتخاب می‌کند یا ثبت اقلام را به راننده می‌سپارد. سفارش با وضعیت «منتظر جمع‌آوری» در شعبه سرویس‌دهنده ساخته می‌شود، یک جا از بازه رزرو می‌شود و پیامک تأیید می‌رود؛ هزینه ارسال و حداقل سفارش از محدوده می‌آید. تا پیش از جمع‌آوری، مشتری (یا کارکنان شعبه) می‌توانند سفارش را لغو کنند و جای بازه آزاد می‌شود. پرداخت آنلاین هنوز نیست؛ پرداخت هنگام تحویل است.

نقشه‌ها از کاشی‌های OpenStreetMap استفاده می‌کنند؛ برای استفاده عملیاتی در پرتال مشتری، `NEXT_PUBLIC_MAP_TILE_URL` و `NEXT_PUBLIC_MAP_ATTRIBUTION` را به سرویس‌دهنده نقشه‌ای که با آن قرارداد دارید تغییر دهید.

### فاکتور رسمی

مشخصات فروشنده (شناسه ملی، کد اقتصادی، نشانی و …) در «تنظیمات ← فاکتور رسمی» است. در صفحه سفارش، «صدور فاکتور» مشخصات خریدار حقیقی یا حقوقی را می‌گیرد (کد ملی و شناسه ملی با رقم کنترل بررسی می‌شوند) و فاکتور شماره بعدی را صادر می‌کند؛ تخفیف و مالیات سفارش بین ردیف‌ها پخش می‌شود و هزینه ارسال ردیف جداست. فاکتور A4 با صفحه چاپ مرورگر چاپ یا PDF می‌شود. فاکتور ویرایش نمی‌شود: با دلیل باطل می‌شود و شماره‌اش دوباره به کار نمی‌رود. تا فاکتور سفارشی باطل نشده، اقلام آن سفارش تغییر نمی‌کند و لغو نمی‌شود. مجوزها جدا هستند: مشاهده، صدور و ابطال.

### هزینه‌ها

هزینه‌های هر شعبه (اجاره، دستمزد، مواد مصرفی و …) با دسته، تاریخ، مبلغ و روش پرداخت در «هزینه‌ها» ثبت می‌شود؛ دسته‌ها قابل تعریف‌اند و سازمان تازه با چند دسته پیش‌فرض شروع می‌کند. هزینه نقدی می‌تواند «از صندوق» پرداخت شود: مبلغ از شیفت باز همان شعبه برداشت می‌شود و با حذف هزینه (تا شیفت باز است) برمی‌گردد. گزارش فروش هزینه‌های همان بازه را کنار فروش نشان می‌دهد: ستون هزینه در گروه‌بندی روزانه و شعبه، جمع به‌تفکیک دسته، و «فروش بدون مالیات منهای هزینه‌ها»؛ خروجی اکسل هم همین را دارد.

### مشتریان سازمانی

در «مشتریان سازمانی» هر سازمان (هتل، رستوران، …) با مشخصات حقوقی و قرارداد تعریف می‌شود: شماره و مدت قرارداد، لیست قیمت قراردادی، سقف اعتبار و مهلت پرداخت، و واحدها (با کد مرکز هزینه). مشتریانی که برای سازمان سفارش می‌دهند به آن وصل می‌شوند؛ سفارش آن‌ها در صندوق به حساب سازمان و یکی از واحدهایش ثبت می‌شود. لیست قیمت قراردادی در «کاتالوگ ← ماتریس قیمت» ساخته می‌شود (خالی یا کپی قیمت‌های پیش‌فرض با درصد تغییر)؛ تا وقتی قرارداد جاری است قیمت‌های آن جای قیمت پیش‌فرض را می‌گیرد و خانه‌های خالی همان قیمت پیش‌فرض می‌مانند. سازمانِ دارای حساب اعتباری تا سقف اعتبار نسیه سفارش می‌دهد و سفارشش بدون تسویه تحویل می‌شود؛ سفارشی که بدهی را از سقف بالاتر ببرد ثبت نمی‌شود.

### حساب‌های نمونه

رمز همه `password` است.

| نام کاربری | نقش | دسترسی |
|---|---|---|
| `admin` | مالک | همه چیز |
| `manager` | مدیر شعبه (شعبه مرکزی) | صندوق، سفارش‌ها، لغو و بازپرداخت، صدور فاکتور رسمی، ثبت هزینه‌های شعبه، مشاهده مشتریان سازمانی، مشاهده کاتالوگ و پیامک‌ها، کارگاه (اسکن، مونتاژ، قفسه، بارنامه، برون‌سپاری)، خسارت و مفقودی، گزارش فروش و تولید، کاربران شعبه، محدوده‌های سرویس و بازه‌های جمع‌آوری شعبه |
| `accountant` | حسابدار | مشاهده سفارش‌ها و شیفت‌های همه شعبه‌ها، صدور و ابطال فاکتور رسمی، هزینه‌ها و دسته‌های هزینه، مشتریان سازمانی و قراردادها، ردیابی قطعه، گزارش فروش و تولید |
| `cashier`، `cashier2` | پذیرش و صندوق | ثبت سفارش، دریافت پول، شیفت صندوق، تحویل، مونتاژ و قفسه، بارنامه به کارگاه |
| `operator` | اپراتور کارگاه (کارگاه مرکزی) | ایستگاه اسکن، تابلوی تولید، دریافت بارنامه، برون‌سپاری، گزارش تولید |
| `driver` | راننده | مشاهده مشتریان، محدوده‌ها و بازه‌های جمع‌آوری (اپ راننده در ادامه فاز ۴) |

## تست و کیفیت

بک‌اند:

```bash
cd backend && vendor/bin/pint --test && vendor/bin/phpstan analyse && vendor/bin/pest
```

فرانت:

```bash
cd frontend && npm run typecheck && npm run lint && npm test
```

تست سرتاسری (Playwright) هر دو سرور را خودش بالا می‌آورد و پایگاه داده `laundry_e2e` را هر بار پاک و با داده نمونه پر می‌کند:

```bash
cd frontend && npx playwright test
```

## تغییر API

1. کد بک‌اند را تغییر دهید.
2. قرارداد را دوباره بسازید: `php artisan scramble:export` در `backend/` (پایگاه داده باید مهاجرت‌شده باشد، چون نوع ستون‌ها از آن خوانده می‌شود).
3. نوع‌های فرانت را به‌روز کنید: `npm run api:types` در `frontend/`.

خط لوله CI (`.github/workflows/ci.yml`) اگر یکی از این دو فایل با کد هم‌خوان نباشد خطا می‌دهد.
