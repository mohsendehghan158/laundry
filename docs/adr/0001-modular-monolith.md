# ۰۰۰۱. یکپارچه ماژولار با Laravel، فقط API

- وضعیت: پذیرفته
- تاریخ: 2026-11-24

## زمینه

دامنه بزرگ است (صندوق، کارگاه، لجستیک، مالی، B2B، وفاداری) ولی تیم کوچک است و یک پایگاه داده تراکنشی مشترک لازم است: ثبت سفارش، پرداخت و صدور قطعه باید در یک تراکنش انجام شوند. ریزسرویس‌ها هزینه استقرار و هماهنگی دارند که این مرحله توجیهش نمی‌کند.

## تصمیم

- یک برنامه Laravel که فقط API سرو می‌کند؛ رابط کاربری کاملاً در Next.js است.
- کد دامنه در `backend/app/Modules/<Module>` با ساختار یکسان: `Actions`، `Models`، `Http`، `Policies`، `Database`، `routes.php`.
- هر ماژول مهاجرت‌ها و مسیرهای خودش را دارد و `ModuleServiceProvider` آن‌ها را با قرارداد نام‌گذاری پیدا می‌کند؛ همه مسیرها زیر `/api/v1`.
- کنترلر نازک: اعتبارسنجی در `FormRequest`، منطق در `Action`، خروجی در `Resource`.
- لایه HTTP (کنترلر، FormRequest، Resource) و Policyهای هر ماژول خصوصی است؛ ماژول‌های دیگر فقط از مدل‌ها، Enumها، رویدادها و Actionهای آن استفاده می‌کنند. تست معماری Pest (`tests/Arch`) این مرز و نازک‌ماندن کنترلرها را کنترل می‌کند.

## پیامدها

- افزودن ماژول تازه = ساخت پوشه + افزودن نامش به `ModuleServiceProvider::MODULES`.
- اگر روزی ماژولی (مثلاً اعلان‌ها) باید جدا شود، مرز روشنش از قبل وجود دارد.
- یک فرایند استقرار و یک پایگاه داده برای پشتیبان‌گیری.
